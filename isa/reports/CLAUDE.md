# CLAUDE.md — isa/reports/

## What lives here

- `xmss_rv64_isa_profile.tex` — Hand-written LaTeX report (the deliverable).
  Covers methodology, rv64gc findings, the Zbb comparison (rv64gc vs
  rv64gc_zbb), recommended Jasmin targets, and next steps. Author: Wrenna
  Robson, with Claude co-authorship noted in a footnote.

- `xmss_rv64_isa_profile.pdf` — Compiled from the .tex. Rebuild with:
  ```bash
  cd isa/reports && pdflatex xmss_rv64_isa_profile.tex && pdflatex xmss_rv64_isa_profile.tex
  ```
  (Two passes for cross-references.)

- `xmss_rv64_isa_profile_reference.tex` / `.pdf` — Companion report
  profiling the upstream XMSS reference implementation
  (`third_party/xmss-reference/`). Stands alone: does not reference our
  C implementation. Key caveat documented in the report: the reference's
  `hash.c` delegates SHA-256/SHA-512 to OpenSSL, so SHA-2 internals are
  NOT in the analysed archive — only SHAKE (via bundled `fips202.c`).
  Rebuild via the same `pdflatex` two-pass command on the `_reference.tex`
  file.

- `xmss_rv64_isa_profile_comparison.tex` / `.pdf` — Side-by-side
  comparison of the two implementations, synthesised from the two
  companion reports above. Covers headline counts, M-instruction
  composition, per-module alignment, and Zbb uptake. Two load-bearing
  findings: (1) the 1942-insn archive-size gap is almost entirely our
  bundled SHA-2 (1953 insns); (2) Zbb lands ≥82% in the hash layer in
  both cases, but with different mnemonic mixes (our archive sees
  32-bit SHA-2 rotations + rev8; the reference sees more 64-bit Keccak
  rotations, because its SHA-2 is opaque-in-libcrypto).

- `.gitignore` — TeX auxiliary files (from github/gitignore TeX.gitignore).

## What is NOT committed (generated on demand)

- `xmss_rv64_isa_profile.md` — Auto-generated by `isa/scripts/analyse.sh`
  against our C impl's `libxmss.a`. Do not commit (would go stale).
- `xmss_rv64_isa_profile_reference.md` — Auto-generated by running
  `analyse.sh` against `isa/binaries/libxmss-ref-rv64gc.a` (produced by
  `isa/scripts/build_reference_lib.sh`). Do not commit.

## How the data was produced

1. `isa/scripts/gen_lookup.sh` generates an authoritative mnemonic→extension
   lookup table from the `third_party/riscv-opcodes` submodule.

2. `isa/scripts/analyse.sh [INPUT] [REPORT]` disassembles the given
   archive (default: `impl/c/build-rv/libxmss.a`), classifies every
   instruction using the lookup table, and writes the .md report
   (default: `xmss_rv64_isa_profile.md`, override via second arg).

   For the reference-implementation companion report, first cross-compile
   the reference sources:
   ```bash
   isa/scripts/build_reference_lib.sh rv64gc       # → isa/binaries/libxmss-ref-rv64gc.a
   isa/scripts/build_reference_lib.sh rv64gc_zbb   # → isa/binaries/libxmss-ref-rv64gc_zbb.a
   isa/scripts/analyse.sh isa/binaries/libxmss-ref-rv64gc.a \
                          isa/reports/xmss_rv64_isa_profile_reference.md
   ```
   The Zbb-variant archive is analysed the same way; the .tex transcribes
   the delta into Tables 3–4 of the reference report.

3. The Zbb comparison in the .tex (Section 4.1–4.2, Tables 3–4) was
   produced by `isa/scripts/compare_zbb.sh`, which builds `libxmss.a`
   with both `-march=rv64gc` and `-march=rv64gc_zbb` in fresh temp
   directories (avoiding stale CMake cache issues), runs `analyse.sh`
   on each, and prints a summary comparison. To reproduce:
   ```bash
   isa/scripts/compare_zbb.sh
   ```
   The data is then manually incorporated into the .tex.

## Key decisions

- The .tex is the source of truth for analysis and commentary. The .md
  is a raw data dump useful for spot-checking but not authoritative.
- The .tex includes hand-written interpretation (the Zbb comparison,
  "where Zbb lands" breakdown, Jasmin target recommendations) that goes
  beyond what the script produces.
- If the C implementation changes significantly (new modules, different
  compiler version), re-run the scripts and update the .tex manually.
